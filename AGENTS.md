Do not recreate it.## Auth (today)- Ktor issues its own JWTs (JWT_SECRET env var, required, no default).  Access token 15 min, refresh token 30 days (refresh_tokens table).- Supabase Auth IS used. 5 demo accounts exist with password demo12345: dr.smith@mediq.app, dr.chen@mediq.app, sec.jones@mediq.app, dr.garcia@mediq.app, admin@mediq.app.- Web stores the session (including refresh token) in sessionStorage. RLS policies ACTIVE on profiles, users, appointments, message_threads, messages tables..- Ktor connects as the table owner (bypasses RLS). Do NOT switch it to a  limited role without adding policies first.- Never edit existing migrations; add new timestamped ones.## Decision in progressLong-term plan: migrate to Supabase-only and delete Ktor.- Supabase Auth replaces Ktor's auth, OTP and refresh tokens.- CRUD routes become direct Supabase queries protected by RLS policies,  with a profiles table and a current_role() helper for roles  (patient, doctor, secretary, admin).- Business logic becomes Postgres functions (RPC), one transaction each:  book appointment (conflict check), confirm/cancel, record outcome,  send message, availability.- Admin create-account becomes one Edge Function (needs service-role key).- Message/notification polling becomes Realtime.- audit_logs writes become database triggers.- Android moves to the Supabase Kotlin client, Angular to supabase-js.Migrate in phases. Ktor keeps running until each route group is moved.Alternative if time is short: keep Ktor as the only backend with RLS deny-all.## Ktor route inventory (about 45 routes)Mostly CRUD.
